# 快捷窗口与桌面便签统一体验建议

日期：2026-10-25。本文记录已确认的统一方案及验收要求。共享面板与编辑会话已实现，最终验收状态见文末。

## 统一目标

便签是同一份内容对象，快捷窗口与桌面贴纸是访问它的两个位置。同一张便签应有相同的标题、正文、颜色、附件、收藏状态和保存结果。窗口大小、位置、透明度和是否置顶属于容器设置，不应被误认为便签本身的属性。

核心采用同一原生 Markdown 编辑器，继续遵守不新增应用依赖的决定。UI 保留现有 WinUI 外观，用同一个便签详情面板保证操作一致；两个入口各自保留适合自身场景的集合导航和窗口操作。

## 实施前的差异及根因

| 能力 | 快捷窗口便签 | 桌面便签/随记详情 | 统一方向 |
| --- | --- | --- | --- |
| 标题 | 独立标题输入框，可命名 | 详情没有对等的标题编辑入口 | 同一个可内联编辑的标题区 |
| 便签颜色 | 缺少入口，便签展示模型也没有颜色字段 | 已有默认、纸张、黄、玫瑰、薄荷、蓝色材质 | 同样的颜色按钮与预设，写入同一个便签属性 |
| Markdown | 本轮已接入新内核，仍没有格式工具栏 | 通过已有工具栏容器接入新内核 | 同一编辑面板与工具栏，窄窗口按同一规则溢出 |
| 附件 | 早期模型没有带出附件，近期已接回展示数据 | 已有添加、打开、移除、拖入等能力 | 两边提供同样的附件条与操作 |
| 保存 | 独立防抖和标题/正文保存流程 | 独立编辑/阅读切换和保存状态 | 统一保存状态与提交边界 |
| 关闭 | 标签关闭会写入 ArchivedAt，进入已关闭列表 | 列表没有按同一字段过滤 | 关闭视图与修改便签生命周期必须分开 |
| 删除 | 确认永久删除，没有对等的撤销反馈 | 已有删除快照与撤销反馈 | 两边使用同一删除流程和恢复能力 |
| 固定/置顶 | 快捷窗口有自己的置顶状态 | 记录可固定到固定分类，容器也能置顶 | 文档收藏与窗口置顶使用不同名称、作用域 |
| 从便签提取待办 | 有正文下方入口 | 没有对等的便签操作入口 | 放进共享的便签操作菜单 |
| 集合导航 | 多标签、已关闭便签 | 随记/固定/剪贴板及主从列表 | 导航形态可以不同，查询同一便签库和同一状态 |

根因是共用存储不等于共用产品逻辑。当前底层 QuickCaptureItem 已包含 Title、Body、AppearancePreset、Attachments、IsPinned、ContentFormat 等属性，QuickCaptureService 也已支持同时更新标题、正文、颜色及格式；但 QuickPanelNotesView/QuickPanelViewModel.Notes 与 QuickCaptureSurfaceContent 各自实现了不同的投影、命令和状态流程。

服务目前的标题更新语义是：未传标题时保留原值，显式传空字符串时清除标题。因此桌面端缺少命名入口主要是 UI 和编辑状态缺失，不需要新造一套标题存储。

## 建议的共同便签面板

两个入口都使用以下结构，顺序和操作位置一致：

```text
[便签标题，可直接编辑]                 [收藏] [颜色] [更多]
[加粗] [斜体] [标题] [任务] [链接] [更多格式]

正文：同一个原生实时 Markdown 编辑器

[附件缩略图 / 文件]                         [添加附件]
已保存 / 正在保存 / 保存失败·重试              更新时间
```

标题、颜色、更多操作属于便签属性；格式工具栏属于正文编辑。两行分组保留清楚的含义，不把颜色、删除、标题等动作混进 Markdown 格式菜单。窄窗口把较少使用的格式动作收入“更多”，两边使用同一个溢出规则，不出现某个入口缺失能力的情况。

### 标题

两边都能直接点击标题命名。独立标题不强迫用户把正文首行改成标题。未命名时列表可使用正文首行的纯文本摘要，没有正文时显示“未命名便签”；摘要只用于展示，不自动写回标题。用户手动命名后，编辑正文不会覆盖该名称；清空名称才恢复摘要规则。

### 颜色

共用现有 AppearancePreset，不为快捷窗口新增另一套配色数据。颜色入口在标题旁，使用同样的六个预设和选中反馈。便签正文卡片反映颜色；顶部标签不显示颜色圆点，通过选中背景与边框强调当前便签。快捷窗口的待办页、剪贴板页和整个窗口背景不跟着某张便签变色。

“默认”跟随当前主题。黄、纸张等预设在明暗主题下保持同一颜色含义，并使用适合主题的颜色值，保障正文、选区和表格的对比度。窗口主题和透明度仍在窗口设置中管理。

### 编辑与格式工具栏

Markdown 便签默认使用实时预览，正文获得光标后展开活动位置的源码，其余内容保持格式化。不再让一个入口始终可编辑、另一个入口必须额外进入“编辑模式”才能得到相同能力。

工具栏默认固定在标题下方，两个入口都有，初期不增加自动隐藏或浮动工具栏状态。点击工具栏、颜色面板、附件菜单仍属于同一编辑范围，保留正文选区。Ctrl+B/I/K、Tab 缩进、任务续行、撤销重做遵循相同规则。已有纯文本记录保持纯文本语义，不因升级而重新解释其内容；新建便签默认 Markdown。

新建时自动聚焦正文；打开已有便签保留原有阅读位置和选择。桌面常驻视图不因后台刷新主动抢焦点。具体窗口激活由宿主决定，便签面板内部交互相同。

### 附件与待办

添加、拖入、打开、删除附件在两个入口保持同样的能力和反馈。Markdown 内嵌图与附件条引用同一附件记录，不能因为存储把记录分类成图片，就让它从快捷窗口的便签列表消失。

“提取为待办”放在共享的更多菜单中，两个入口都提供。提取前读取已同步的当前正文；用户应能确认提取结果，避免重复操作时无提示地创建重复任务。

### 关闭、删除与收藏

关闭快捷标签只结束该标签的显示，不修改正文，不删除内容，也不应把便签从桌面便签库中隐藏。收起快捷窗口、关闭桌面容器同样只影响视图。已关闭的标签通过便签列表重新打开；只有明确的删除动作才移除内容。

当前 ArchivedAt 实际承载快捷窗口的关闭历史。统一时须完整保留这些记录及可重新打开能力，先把打开标签和关闭历史转为宿主视图状态，再调整共享库的过滤规则；不能简单给桌面列表加过滤而让原本可见的内容突然消失。

文档操作建议使用“收藏便签”，对应现有 IsPinned；窗口操作使用“窗口置顶”。两者图标提示、菜单位置和状态应明确区分。删除沿用现有快照与撤销机制，两边一致，避免一边强调永久删除而另一边可以撤销。

## 保存与跨入口同步

标题、正文、颜色和附件通过同一便签编辑会话提交。统一“正在保存 / 已保存 / 保存失败·重试”的状态及延迟规则，关闭、切换便签、切换宿主之前都先同步原生编辑缓冲，再处理保存结果。保存失败保留草稿，不能关闭后悄悄丢弃，也不能显示“已保存”。

两边打开同一 Id 时，修改标题、颜色或正文，应刷新另一边的对应内容。当前用户在同一台电脑上使用两个入口，可先采用同一时刻由一个有焦点的正文编辑器提交输入、焦点交接前同步缓冲的规则；不需要引入多人协同算法。后台刷新不得用旧缓存覆盖新内容，也不应在输入法组字期间重新绑定正文。

各入口的窗口尺寸、标签顺序、滚动位置等视图状态可分别保存。便签内容属性共用，不把“在哪个窗口打开”写进便签业务状态。撤销重做先保持对当前便签有效，禁止串入另一张便签的历史；跨宿主共享整条撤销历史不作为第一阶段前提。

## 推荐实现边界

1. 保留 QuickCaptureItem 与 QuickCaptureService 作为数据来源，统一标题、颜色、附件、便签资格筛选和动作语义，不新增平行便签存储。
2. 在现有 MarkdownLiveEditor 与工具栏能力之上形成一个共享的便签详情控件，包含标题、便签操作、格式栏、正文、附件及保存状态。快捷窗口与桌面详情都直接承载它，避免分别复制一套按钮和处理器。
3. 共用便签编辑会话与保存流程。宿主仅负责打开哪张便签、显示标签还是列表，以及窗口移动、显示、隐藏和置顶。
4. 分开处理生命周期与历史数据兼容，保留当前已关闭记录；共享查询不能继续因入口不同而漏掉带附件的 Markdown 便签。

## 实施顺序与验收

先完成新编辑器在两个真实入口的接入与保存边界，再统一共享详情面板，同时补齐命名、颜色、格式栏、附件和待办入口。最后处理关闭历史、收藏名称及跨入口同步，避免只补图标而继续保留相互矛盾的业务状态。

验收使用同一张真实测试便签：在快捷窗口命名和改颜色，桌面立即显示同名同色；在桌面改名、添加附件及编辑正文，快捷窗口显示同一结果。两个入口分别验证格式工具栏选区、中文输入、撤销重做、快速切换、关闭前输入、保存过程中继续输入、保存失败保留草稿、关闭后重新打开和删除撤销。两个主题与窄/宽窗口都检查，不用单独的编辑器探针替代入口验收。

## 实施结果与验收记录

两个入口现均承载 NoteEditorPane。它复用原生 MarkdownLiveEditor 和现有格式工具栏，包含标题、收藏、颜色、便签操作、正文、附件条及保存状态。NoteWorkspace 按便签 Id 共享 NoteEditingSession；标题、正文、颜色与格式按有改动的字段保存，避免元数据操作覆盖另一入口的新正文。原生缓冲在焦点交接、切换和保存前同步，保存等待期间的新输入也会继续提交。

新建便签可以保持空白及未命名，默认使用 Markdown；旧纯文本记录保持原格式。未命名时，标签摘要仅用于展示，不写回标题。快捷标签关闭状态已移至存储根节点的独立历史；版本 5 迁移保留原 ArchivedAt 的时间及可重新打开能力，不改变正文和便签更新时间。删除与撤销、收藏、附件操作和待办提取共用同一流程。待办导入前显示候选项，并按标题跳过重复任务。

顶部标签按最终确认的交互去掉圆点，以背景和边框突出当前标签。选项卡选择由宿主在保存成功后同步，避免异步选择流程与单向绑定互相覆盖。颜色仍体现在便签卡片，窗口置顶与收藏便签使用不同名称。

验收使用独立开发数据目录中的测试便签，实际创建 QuickPanelNotesView 与 QuickCaptureSurfaceContent 两个生产控件，并同时打开同一 Id。自动检查已确认双向标题/颜色/正文同步、附件添加和移除、收藏、关闭后桌面继续可见、重新打开及删除撤销。立即切换前的输入和保存过程中继续输入均被保留。保存失败保留草稿、释放视图后重新获取同一草稿和恢复存储后重试由服务回归覆盖。

已导出并逐张检查两个主题及窄窗口的应用内控件截图。验收程序仅在截图用的标签控件中禁用容器入场过渡，避免 RenderTargetBitmap 捕获到过渡起点而漏掉标签；产品使用原生标签选中样式，当前标签会滚动至可见位置。预览缓存现包含主题、字号和文字颜色；外观变化后重建受影响的表格/图片视图，避免复用旧文字颜色。异步解析也携带实际渲染状态与代次，避免旧 Markdown 或旧主题的解析结果覆盖新视图。截图位于 .debug-data/md-editor/notes-unified-*.png，原始检查结果位于 native-markdown-probe.json。

最近全量回归为 5865/5870，通过之外是此前相同的五项失败：三个 AOT 绑定提供器数量契约、可用贴纸类型列表和贴纸组关闭确认契约。本次新增的版本迁移断言、全局服务访问和模板文字阴影问题已消除。扩展定向回归 453/453；最后的 Markdown、便签和文字阴影回归 214/214。全量测试没有被表述为全部通过。

当前 goal 保持进行中。上述截图来自应用自己的 RenderTargetBitmap，业务及缓冲检查来自实际控件和存储，不等同于新一轮真实鼠标、拖放或中文组字操作。用户通过 Esc 停止 Computer Use 后，本轮未再注入鼠标键盘，相关交互复验尚未补齐；早先中文输入正常的用户反馈仍保留为此前内核验收证据。没有新增应用依赖，没有进行零售发布，也没有删除发布产物。
